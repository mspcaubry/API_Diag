Pas d'accès PC ? Commence par observer l'automate, l'IHM et les voyants physiques. Ces informations suffisent souvent à orienter le diagnostic.

1

État général de l'automate

Observe les voyants sur le boîtier de l'API. Que vois-tu ?

🖥️ Voyants façade automate (TSX / S7 / M340...)
RUN (vert)
Programme en cours d'exécution
ERR / STOP (rouge)
Défaut automate ou programme arrêté
BAT (orange) / I/O ERR
Défaut batterie ou défaut carte E/S
COM (vert clignotant)
Communication bus/réseau active

✓ API en RUN. Le programme tourne normalement. La panne est d'origine électrique, pneumatique, mécanique ou capteur — pas un défaut API. Continuer l'observation.

2

Voyants des cartes Entrées / Sorties

Observe les LED sur les cartes d'entrées et de sorties de l'automate.

Comment lire les cartes :
Chaque LED correspond à une voie (I0.0 → I0.15 pour les entrées, Q0.0 → Q0.15 pour les sorties).
LED allumée = voie active (1)  |  LED éteinte = voie inactive (0)

Cartes SORTIES (Q / O)

La LED de la sortie commandant l'actionneur concerné est-elle allumée ?

Sortie inactive (LED éteinte). L'automate ne commande pas. La panne est soit dans la chaîne d'acquisition (TYPE 2) soit dans les sécurités (TYPE 3). Continue l'observation des entrées.

Cartes ENTRÉES (I)

Les LED des capteurs liés au sous-système en panne — leur état est-il cohérent avec la position réelle ?

✓ OUI — LED cohérentes avec les positions
✗ NON — une LED est incohérente (capteur?)
⚠ Entrée de sécurité éteinte (AU, porte...)

⚠ Entrée de sécurité éteinte. Un AU, une porte, un pressostat ou un thermique n'est pas satisfait → TYPE 3 probable (chaîne sécurité / démarrage).

Synthèse et orientation

En fonction de tes observations, voici le diagnostic préliminaire.

API en RUN — programme en cours d'exécution

LED sortie éteinte → automate ne commande pas (TYPE 2 ou 3)

Entrée sécurité inactive (TYPE 3 — sécurité/démarrage)

Orientation : TYPE 3 — SÉCURITÉ / DÉMARRAGE
Passe aux tests correspondants ou affine avec le logiciel automate si disponible.

Accès logiciel disponible. Ouvre la table d'animation du logiciel automate (PL7 / TIA Portal / Unity Pro) et réponds aux questions.

💡 Si tu n'as pas accès au logiciel, utilise l'Observation API à la place (voyants physiques + IHM).

Question 1 / 3 — Table d'animation
La SORTIE automate est-elle à 1 ?
Table d'animation → colonne Sorties (Q / O) → la sortie commandant l'actionneur
💡 Ex ECOLPAP : O1,0 = SOVT. Vérifie aussi la LED correspondante sur le module de sortie physique.
Question 2 / 3 — Grafcet
Le Grafcet attend-il un capteur ?
Animation Grafcet → étape active → attend une entrée I = 0 ?
💡 Regarde aussi les LED des cartes d'entrées. Si une LED est éteinte alors que le capteur devrait être actif → panne acquisition.
Question 3 / 3 — Sécurités
Une entrée de sécurité est-elle à 0 ?
Table d'animation + cartes entrées + IHM :
AU · Sélecteur · REAR · Positions initiales · Pressostat · Thermique · T° four
💡 L'IHM affiche souvent directement le défaut de sécurité (ex: "AU enfoncé", "Porte ouverte").
